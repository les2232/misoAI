# Miso Feature Ideas

## Main Problem

Miso helps me recover context when I come back to my computer and do not remember where I left off.

Miso should help answer:

- What was I working on?
- What projects are active?
- What is the next step?
- What did I last finish?
- What should I pick back up first?

## Core Identity

Miso is a cute, personal Raspberry Pi desk-buddy assistant.

Miso should be personal, local-first, safe, encouraging, useful, and small enough to understand.

Miso should not become a work assistant or store institutional data.

## Must-Have Features

- Recap / workboard
- Resume a project
- Project handoff summary
- Daily check-in
- Focus helper
- Local memory
- Voice output

## Key Commands To Build

- recap: show active projects and where to resume
- resume <project>: show status and next step for one project
- handoff <project>: create a pasteable summary for ChatGPT, Claude, Codex, or notes
- checkin: run a daily check-in
- focus: start a focus helper
- stuck: help break work into one tiny next step
- say <message>: speak typed text out loud

## Later Features

- Check-in history summaries
- Wins log
- Project milestones
- Simple task priorities
- Local dashboard
- Browser page at miso.local
- Voice command improvements
- Data export
- Data wipe/reset command

## Dream Features

- Voice input
- Wake word
- Cute robot body
- LED status light
- Tiny screen or face display
- Button input
- Motion sensor
- Expressive sounds
- Small gestures or servo movement
- Proactive daily briefing

## Safety Rules

Miso is a personal project.

Miso should stay separate from work systems, institutional servers, institutional data, private student/staff/faculty information, and anything requiring workplace authentication.

Miso can help me think through work-like problems, but it should not store private work data.

## Recommended Build Order

1. Keep the CLI stable
2. Add feature brainstorm doc
3. Add project vision doc
4. Build recap command
5. Build local project tracker
6. Build resume project command
7. Build handoff command
8. Improve daily check-in
9. Add focus helper
10. Add dashboard later
11. Add hardware features after the software feels useful
